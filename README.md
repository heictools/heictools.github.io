# HEIC Tools

**[Free HEIC to JPG converter → https://heictools.github.io/](https://heictools.github.io/)**

Convert HEIC/HEIF photos to JPEG entirely in the browser. Multiple-file queues,
individual JPEG downloads, ZIP archives, adjustable quality, and optional resizing.
No photo uploads, accounts, backend, database, paid API, or runtime CDN dependencies.

## Run locally

Install Node.js 22 or later (with npm), then:

```sh
npm ci
npm test
npm run build
npm run dev
```

Open http://127.0.0.1:4173. Re-run `npm run build` after editing; the preview
serves `dist/` without a file watcher. Do not open index.html using `file://`:
ES modules and workers need HTTP(S). The build output is entirely static.

## Features

- Drag and drop or pick multiple files; append more without replacing the queue.
- Sequential processing with visible decoding/encoding stages and overall progress.
- Remove/cancel individual images; clear all; retry failed items.
- 60–100% JPEG quality (90% default).
- Original dimensions, half size, 1920 px longest side, or custom bounding box.
- Aspect ratio preserved; never upscales. Optional filename suffix.
- Output thumbnails, dimensions, sizes, and individual downloads.
- ZIP of successful conversions with case-insensitive duplicate-name resolution.
- No arbitrary file-count limit; memory guidance and bounded decode concurrency.
- Semantic static content, keyboard controls, responsive layout, accessible status.
- Distinct converter, batch, JPEG, comparison, Mac, and iPhone pages.
- Canonicals, Open Graph image, robots.txt, sitemap.xml, truthful WebApplication data.

## How it works

The initial converter JavaScript is small; the approximately 3 MB heic-to decoder
is fetched on first conversion. A new module worker per image imports the unchanged
`heic-to/next` library, whose internal worker decodes the primary HEIF image.
An ImageBitmap is encoded once as JPEG at the requested dimensions using an sRGB
canvas. OffscreenCanvas handles encoding off the main thread where available;
otherwise a transferred bitmap is encoded in a regular canvas on the main thread.
Current Worker and createImageBitmap support are required.

Each job terminates its worker subtree when complete, cancelled, failed, or timed
out (3 minutes). This frees decoder memory between files. Decoded bitmaps are closed
and canvases reset. Original File references are released after successful conversion;
only compressed JPEGs and small thumbnails remain. Output URLs are revoked on removal,
clear, and page exit. A reload discards unsaved outputs.

JSZip loads only when requested. ZIPs use STORE because JPEG data is already
compressed. ZIP construction yields through JSZip's async API but retains archive
data in memory; it is not a streaming-to-disk exporter. Download and clear smaller
groups if memory is tight. The explicit Save ZIP link after preparation supports
mobile user-gesture download requirements. Choosing a resize cannot remove the
need to decode the original full-resolution photograph first.

### Appearance and metadata limits

- One primary still image is exported. No Live Photo video, depth map, auxiliary
  frame, animation, or HDR gain-map preservation.
- HEIF container orientation is delegated to libheif. A bounded metadata reader
  applies EXIF orientation only when the primary item has no container transform,
  avoiding double rotation. Ambiguous multiple EXIF items, malformed metadata, and
  metadata larger than 16 MB are skipped. Check unusual sources visually.
- Standard 8-bit JPEG output. Original EXIF (including GPS/date/camera) and ICC
  metadata are not copied. The browser may add encoder metadata.
- The canvas requests sRGB, but this decoder path does **not** guarantee color-managed
  ICC conversion or faithful HDR tone mapping. P3/HDR sources may visibly differ.
  Use a native color-managed photo application for critical photographic work.
- JPEG encoding is lossy even at 100%. Keep originals; do not treat results as
  archival replacements. Damaged files and unsupported HEIF codecs fail per item.
- Browser and OS memory limits remain; a killed mobile tab cannot be recovered.

## Testing

```sh
npm test
npm run build
npx playwright install --with-deps chromium firefox webkit
npm run test:browser
```

Browser tests cover real synthetic HEIC decoding in Chromium, Firefox, and WebKit,
plus mobile Chromium/WebKit viewports. They verify JPEG bytes, dimensions, orientation,
ZIP contents, duplicates, Unicode, failure isolation, cancellation, quality settings,
metadata removal, accessibility, and no cross-origin/upload requests. These tests
are not a claim of physical iPhone/Safari or Microsoft Edge certification.

Use `BASE_URL=https://heictools.github.io npm run test:browser` for live-site checks.
See **[testing and release checks](docs/TESTING.md)** for the physical-device and
real-camera matrix and recorded verification limitations. Regenerate synthetic
fixtures only if needed with `scripts/make-fixtures.py` (Python/Pillow/pillow-heif).

## Maintenance

1. Review dependency and GitHub Actions update PRs monthly. Versions are exact-pinned;
   `package-lock.json` pins transitive dependencies. Actions are pinned to commits.
2. Run `npm outdated` and `npm audit`. Inspect upstream changes, especially decoder,
   orientation, memory, color, and browser API changes.
3. Update deliberately with `npm install --save-exact package@version` (or `-D` for
   development tools). Review the lockfile, licenses, and notices.
4. For heic-to changes, refresh the corresponding source archives and BUILD.md in
   `third-party/`, verify bundled libheif/libde265 versions, and run all image tests.
5. Build, test, visually compare important fixtures, and push a reviewed commit.
   Roll back with `git revert` and deploy again if an update regresses conversion.
6. Keep runtime libraries self-hosted. Do not add analytics or widgets without
   revisiting the privacy policy and any applicable consent requirements.

## Troubleshooting

| Problem | Check |
| --- | --- |
| Converter cannot start | Current browser, JavaScript enabled, worker permissions, successful `/vendor/heic-to/next.js` request; reload after deployment |
| Invalid/unsupported photo | Confirm the bytes are HEIC; a renamed JPEG is not HEIC. Try a native Photos/Preview export for unsupported codecs |
| Slow or reloading mobile tab | Use smaller groups, keep tab active, close other tabs, download results and clear |
| ZIP fails | Archive duplicates memory; download JPEGs individually or split the batch |
| Download seems missing | Check the browser Downloads folder and mobile file manager; prepare ZIP, then select Save ZIP |
| Quality/settings did not alter completed files | Settings affect the next batch; remove/re-add originals to reconvert |
| Photos look different | HDR, profiles, and original metadata are not preserved; use native export for critical color |
| GitHub Pages 404 | Correct username.github.io name, Pages source = Actions, successful deploy job, no project subpath |
| Browser library download fails offline | This is not a guaranteed-offline PWA; visit online to load dependencies |
